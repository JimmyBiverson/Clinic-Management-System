

📄 PROJECT HANDOVER DOCUMENT — KOYONZO FAMILY CARE CLINIC SYSTEM

1. PROJECT OVERVIEW

A clinic management system that handles

· Patient registration
· Visits & triage
· Doctor consultations
· Prescriptions & pharmacy dispensing
· Billing & receipts
· Appointment scheduling with reminders
· Management reports for the CEODirector

Current State Built in Microsoft Access (Desktop). Migrating to a web-based system for multi-user, remote access.

---

2. USER ROLES

Role Responsibilities
Receptionist (Staff) Register patients, create visits, view appointments, print receipts
Triage Nurse Enter vitals (BP, Temp, Pulse, Weight, Height, BMI, Chief Complaint, Lab Tests)
Doctor View waiting list, add consultation notes, prescribe drugs, set next appointment
Pharmacist Dispense drugs, mark as billed
Cashier Generate receipts, accept payment (Cash  M-PESA  Card  Insurance)
Administrator Manage users, drugs, services, prices, visit types

4. THE COMPLETE USER WORKFLOW

STEP 1 Patient Arrives

· Receptionist opens the system → New Patient Registration
· Enters FullName, Phone, Gender, DOB, Insurance, NOKContact
· System generates Serial Number automatically (Format PAT-YYYY-####)
· System creates a Visit for today

STEP 2 Triage

· Nurse opens the Triage screen
· Enters BP, Temp, Pulse, Resp, Weight, Height, Chief Complaint, Lab Tests
· System calculates BMI
· Marks TriageDone = True

STEP 3 Doctor Consultation

· Doctor opens the Doctor's Dashboard
· Sees the Waiting List (patients with TriageDone = True and ConsultationDone = False)
· Selects a patient
· The VisitID field blinks (yellow) to confirm it is linked to the correct patient
· Enters History, Examination, Diagnosis, Treatment
· Prescribes drugs (multiple can be added)
· Sets Next Appointment (optional)
· Clicks Complete Visit → marks ConsultationDone = True

STEP 4 Pharmacy

· Pharmacist opens the Prescription Queue
· Sees all prescribed drugs for today
· Confirms which drugs were given → writes to tblDispensed

STEP 5 Cashier

· Cashier opens the Billing Form
· Selects the patient
· Clicks Import Items from Dispensary
· A dialog shows all unbilled items with numbers
  ```
  1  Thomas Wesonga  Ceftriaxone 1g   Qty 5
  2  Thomas Wesonga  Panadol 500mg    Qty 24
  3  Thomas Wesonga  General Consultation  Qty 1
  ```
· Types 1, 2, 3 → OK
· System inserts into tblBilling, looks up prices from tblDrugs, calculates LineTotals
· Marks IsBilled = True on source rows
· Cashier selects Payment Method (Cash  M-PESA  Card  Insurance)
· Prints receipt

STEP 6 Management Reports

· CEO opens the Management Report dialog
· Types a number (1–10) for the report they want
  ```
  1  = Drug Summary
  2  = Visitor List
  3  = Admitted Patients
  4  = Patients by Service Category
  5  = Top 10 Most Prescribed Drugs
  6  = Doctor Activity
  7  = Visit Types Distribution
  8  = Lab Tests Summary
  9  = Revenue Snapshot
  10 = All Reports Combined
  ```
· Report is generated and copied to clipboard  saved as Excel

STEP 7 Appointments

· Receptionist or Doctor clicks Appointments
· Types a number (1–6)
  ```
  1 = Tomorrow
  2 = Next 5 days
  3 = Upcoming (30 days)
  4 = Missed (60 days)
  5 = All
  6 = Custom range
  ```
· System shows Upcoming  Attended  Missed
· Reminder When the doctor opens the dashboard, a popup shows patients with appointments 2 days from now

5. KEY BUSINESS LOGIC

5.1 — Serial Number Format

```
PAT-YYYY-####
Example PAT-2026-0001
```

Generated automatically on the first save.

5.2 — Age Calculation

```
Age = DateDiff(yyyy, DOB, Today) - 1 if birthday has not passed this year
```

5.3 — Appointment Attendance Detection

· If appointment date is in the future → Upcoming
· If appointment date is in the past AND a Visit exists within 3 days → Attended
· If appointment date is in the past AND no Visit exists → Missed

5.4 — Drug Pricing

· Each drug has a price in tblDrugs.UnitPrice
· When dispensed, price is looked up and stored in tblBilling.UnitPrice
· LineTotal = Quantity × UnitPrice

5.5 — VAT

· Applied at 16% (configurable)
· SubTotal + VAT - Discount = TotalAmount

5.6 — Ghost Record Prevention

· A consultation record is only saved if History OR Examination is not empty
· Otherwise, the save is silently cancelled
